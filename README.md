# Star Detective Precure Web Lab

《名探偵プリキュア！》2026 年活动回忆档案馆的 GitHub Pages 开发实验仓库。

**项目定位：**面向粉丝，通过日历和地图重温已发生的活动。这不是实时活动公告、报名或导航站，也不承诺收录完整性。

## 如何维护

1. 从最新 `main` 创建新的功能分支。
2. 按功能范围修改 `index.html`（日历）、`map.html`（地图）、`event.html`（纪念册）、`data/events-demo.json`（共用演示资料）及有关文档；不要修改无关文件。
3. 提交 Commit，创建 Pull Request，检查 Files changed、交互效果、演示数据来源。
4. 人工批准并合并到 `main`；检查 Actions 的 `pages build and deployment` 是否为 Success。
5. 在电脑和手机分别检查已发布网页。出错时首先检查 PR 变更及 Actions 日志，不要直接覆盖整仓库。

**原型说明：**日历、地图均采用静态 HTML/CSS/JavaScript；地图额外读取仓库内的本地 JSON 边界数据。正式活动数据接入前，应先批准公开字段、去重规则与核查流程。

## 演示活动数据的维护

唯一演示活动数据保存在 [data/events-demo.json](data/events-demo.json)，日历、地图和纪念册共用这一份文件。字段说明见 [docs/EVENT_DATA.md](docs/EVENT_DATA.md)。不要直接把独立研究数据库的内部审计字段发布到网站，也不能以本条演示记录推断全国活动数量。

## 五色视觉主题维护（V1.2 增量）

主题颜色令牌集中在 [assets/theme-v12.css](assets/theme-v12.css)，三张页面在原有基础样式后加载主题覆盖层。上紫用于导航；下粉用于页脚与活动标记；左蓝用于探索区域；右白用于阅读卡片；中金用于选中或中心视觉焦点。调色时先修改主题文件内 `:root`，然后在 PC/iPhone 上检查实际可读性。金色不代表活动数量，地图深灰的「暂无已收录」语义不变。

配色灵感来自「スターキラリングブローチ」的宝石方位；没有直接把道具图片发布到网站，也不将示意设计图当作活动事实。V1.2 历史与当前限制以 [UI 规范](docs/UI_DESIGN_V1.2.md) 为准。

## 地图四色独立高亮（2026-11-20，本轮候选）

在 PR #8 五色主题合并并由用户报告实测无问题后，下一独立分支 `feature/map-multicolor-highlights` 调整地图：**有已收录记录**的每个行政区域，从紫／粉／蓝／白四色中独立伪随机分配一种填充色，边框一律使用金色；**未收录区域维持深灰**。选择区域仍使用更粗的金边（包括未收录区域的选择），不使用金色表示活动数量或证据等级。

颜色由 `map.html` 中 `regionHighlightColor(id,level)` 基于行政层级和行政代码稳定计算：不调用 `Math.random()`，避免切换日期、刷新、返回时跳色；它不是活动类型、数量或行政属性的编码。填充配色及金色边框集中维护于 `assets/theme-v12.css`。目前只有一条 Staff Talk 示例，四色的多区域视觉分布须待正式资料或专用测试环境才能完整评估，不能伪造活动给正式网站展示。

PR #8 主题改造已于 2026-11-20 合并（`0de267d`），并由用户报告 PC/iPhone 测试正常；本轮四色高亮分支未合并之前仍属于候选改动。
