# Star Detective Precure Web Lab

《名探偵プリキュア！》2026 年活动回忆档案馆的 GitHub Pages 开发实验仓库。

**项目定位：**面向粉丝，通过日历和地图重温已发生的活动。这不是实时活动公告、报名或导航站，也不承诺收录完整性。

## 如何维护

1. 从最新 `main` 创建新的功能分支。
2. 按功能范围修改 `index.html`（日历）、`map.html`（地图）、`event.html`（纪念册）、`data/events-demo.json`（共用演示资料）及有关文档；不要修改无关文件。
3. 提交 Commit，创建 Pull Request，检查 Files changed、交互效果、演示数据来源。
4. 人工批准并合并到 `main`；检查 Actions 的 `pages build and deployment` 是否为 Success。
5. 在电脑和手机分别检查已发布网页。出错时首先检查 PR 变更及 Actions 日志，不要直接覆盖整仓库。

**原型说明：**日历、地图均采用静态 HTML/CSS/JavaScript。PR #13 合并后，地图只额外读取仓库内轻量的 `data/map-schematic-layout.json` 布局数据，不加载真实轮廓路径；历史边界 JSON 暂不删除。正式活动数据接入前，应先批准公开字段、去重规则与核查流程。

## 五色视觉主题维护（V1.2 增量）

主题颜色令牌集中在 [assets/theme-v12.css](assets/theme-v12.css)，日历、地图、纪念册和活动档案四张页面在原有基础样式后加载主题覆盖层。上紫用于导航；下粉用于页脚与活动标记；左蓝用于探索区域；右白用于阅读卡片；中金用于选中或中心视觉焦点。调色时先修改主题文件内 `:root`，然后在 PC/iPhone 上检查实际可读性。金色不代表活动数量，地图深灰的「暂无已收录」语义不变。

配色灵感来自「スターキラリングブローチ」的宝石方位；没有直接把道具图片发布到网站，也不将示意设计图当作活动事实。V1.2 历史与当前限制以 [UI 规范](docs/UI_DESIGN_V1.2.md) 为准。

## 地图四色独立高亮（2026-11-20，PR #9 历史方案）

在 PR #8 五色主题合并并由用户报告实测无问题后，下一独立分支 `feature/map-multicolor-highlights` 调整地图：**有已收录记录**的每个行政区域，从紫／粉／蓝／白四色中独立伪随机分配一种填充色，边框一律使用金色；**未收录区域维持深灰**。选择区域仍使用更粗的金边（包括未收录区域的选择），不使用金色表示活动数量或证据等级。

颜色由 `map.html` 中 `regionHighlightColor(id,level)` 基于行政层级和行政代码稳定计算：不调用 `Math.random()`，避免切换日期、刷新、返回时跳色；它不是活动类型、数量或行政属性的编码。填充配色及金色边框集中维护于 `assets/theme-v12.css`。目前只有一条 Staff Talk 示例，四色的多区域视觉分布须待正式资料或专用测试环境才能完整评估，不能伪造活动给正式网站展示。

PR #8 主题改造已于 2026-11-20 合并（`0de267d`），并由用户报告 PC/iPhone 测试正常；PR #9 四色高亮也已合并，但其中固定行政代码抽色的设计后来被否决，见下节。


## 地图随机重抽修正（2026-11-20，PR #10 已合并并验收）

最新设计：**有当前筛选结果的地区每次绘制都从紫／粉／蓝／白独立抽签**；每轮绘制中同一地区颜色一致（包括缩略图），下一轮可重新抽取。抽色使用 `Math.random()` 与仅在 `draw()` 生命周期有效的临时 `Map`，不保证每轮变色、不保证四种颜色均分。已收录区保持金边、选区金边加粗，未收录区仍深灰。配色仍由 `assets/theme-v12.css` 控制。

PR #10 已于2026-11-20合并（`8e3b8fea`），用户报告设备验收成功，现行 `main` 使用每次重绘重新抽签的方案。当前一条 Staff Talk 数据不变；不增加虚构活动。历史见 [UI 设计规范第15节](docs/UI_DESIGN_V1.2.md) 与 [地图数据说明第8节](docs/MAP_DATA.md)。

## PR #12｜跨地区高亮已修复、手机放大方案被后续取代（历史）

在 PR #11 完成用户验收后，优先修复：① iPhone 手机地图整体缩得过小；② 选中无已收录活动的其他都道府县会导致东京的彩色高亮错误消失。候选分支 `fix/map-mobile-visibility-and-highlight-scope` 修改 `map.html` 的手机端地图显示容器和全图活动高亮逻辑；桌面端仍保留全图，手机端改为大幅放大、在地图内通过原生触摸滚动浏览。高亮以时间和类别为依据，不受当前选中的其他行政区干扰。保留来自日历的 `region=other` 初始筛选语义和 PR #10 每次重绘四色抽签规则。

不改动官方研究数据库、演示 JSON、行政边界数据或主题令牌。详情见 `docs/MAP_DATA.md` 第9节与 `docs/UI_DESIGN_V1.2.md` 第17节。PR #12 已于2026-11-20合并（`a3d9b3a1`）；用户确认高亮问题解决，但 iPhone 页面过宽，故手机内部拖动大图方案将被 PR #13 的方块示意图取代。


## PR #13｜全国与东京二级统一方块示意地图（已合并并由用户验收）

**当前有效设计：**以参考图的“日本地区方块示意”理念为方向，用本项目自己的 CSS Grid 布局表现行政单位，而非照搬原图像、假设矩形代表真实边界。全国一级图有47个圆角方块；东京都二级保留全部62个区市町村：本土23区和多摩30个行政单位；伊豆8个、小笠原1个沿用原来的标签切换入口。桌面全国版近似日本地理方位，手机按地区标题改为自适应3列，减少缩放不清和横向滚动。

新数据文件 [data/map-schematic-layout.json](data/map-schematic-layout.json) 只含行政编码、名称、组别及全国桌面方块栅格位置（不包含真实边界数据）。地图不再在浏览器请求 `data/map-prefectures-paths.json`、`data/map-tokyo-paths.json`；两个历史 JSON 保留，许可核查历史记录也保留在 `docs/MAP_DATA.md`。四色重抽、金边、无记录深灰、选区与活动预览独立、日历／档案／纪念册联动保持。演示 JSON 及其他页面不变。

原开发分支 `feature/schematic-tile-maps-v13`；PR #13 已于2026-11-20合并，用户报告 Pages 部署及 PC/iPhone 验收通过。隔离模拟测试不能代替设备验收。参见 [UI规范第18节](docs/UI_DESIGN_V1.2.md) 及 [MAP_DATA第10节](docs/MAP_DATA.md)。
