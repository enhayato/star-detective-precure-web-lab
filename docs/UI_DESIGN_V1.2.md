## 1. 产品目标与边界

网站核心价值是让访客发现「原来 2026 年的那一天、那个地方，还发生过这种探Q活动」。**发现以前不知道的活动**是优先目标，重温本人参与过的活动是次要价值。访客主要是普通粉丝，不以研究人员为首要对象。

不是实时活动导航、购票、报名或预约系统；不承诺数据更新实时性和全国活动穷尽性；不提供精确商场楼层、路线规划或地点导航；首版不引入登录、收藏、管理后台或服务器数据库。

**必要语义：**「暂无已收录记录」不等于「当天／当地没有举办活动」。

## 3. 日历：设计与行为（已认可）

### 3.1 桌面和移动端

- 页面标题「2026年的活动日历」，以年月、地区、活动类型、单日／整月模式筛选。
- 桌面主体视觉比例约 70% 日历 / 30% 活动预览，具体宽度随屏幕调整；手机纵向堆叠，不照搬桌面双栏。
- 单格显示日期数字和简洁标记，**不在格内塞长标题**。选中日期采用明显紫色状态；有已收录条目的日期使用粉色小圆点。
- 选日期不跳页，右侧（手机下方）预览即时改变；进入活动详情才离开日历。
- 手机日期触控区域足够大；卡片标题、举办日期、地点优先可读。视觉稿中的虚构活动数不能照抄。
- 自定义日期范围属于后续范围；原型先实现单日／整月，并保留扩展位置。

### 3.2 日期语义

- 持续数日的同一活动，在覆盖的每个日历日期均可检索，但**不是多份独立活动主记录**。
- 同一活动在多个地点与日期的不同场次需要独立的举办实例，主活动和场次的唯一性／计数待制定正式规则。
- 日期按日本当地历日 `YYYY-MM-DD` 处理，不应因为 UTC 转换发生日期偏移。
- 年月、日期、地区、类型以及跨页状态能从 URL 恢复；PR #6 已完成日历↔地图的时间／类型／粗地区状态继承，具体府县和区市町村仍不能被日历当前较粗的地区筛选完整保留。
- 没有标记的日期意味着「当前筛选范围内无已收录记录」，不是历史上不存在活动。

## 4. 地图：V1.2 真实轮廓历史设计（已被 PR #13 方块示意图方向取代）

> 本节保留真实轮廓图方案的**历史决策原文**，不可再将「必须真实边界」理解为 PR #13 以后的网站有效要求。用户于2026-11-20批准统一使用圆角方块示意图；最新有效地图要求在第18节。行政单位编码仍必须真实，不得将人为区块当作真实行政边界。

- **第一级：**日本 47 都道府县真实边界，以时间过滤后的已收录活动状态高亮。
- **第二级：**所选府县真实行政区划。东京都要细到新宿区、杉並区、渋谷区、世田谷区、豊島区，以及多摩各市町村、岛屿各町村等；其他府县保持合理一致的真实行政单元规则。
- 明确否决「东京23区西部／东部／多摩」等人为粗分区；只保留两级地理浏览，不下钻街道／商场／店铺。
- 无已收录活动的区域使用**深灰**；有记录的区域使用紫／粉／蓝亮色；选中区域边界更清楚，并可加入柔和静态外发光与克制的交互动效。
- **紫粉蓝具体映射规则尚未确定**；视觉稿示意中的“1—2、3—5、6+”和高亮地区、数量不是事实或已经批准的数量级。
- 正式地图使用**有许可依据、可核对的真实日本行政区划 SVG／GeoJSON 或等效边界数据**，记录来源、版本、授权方式及行政区代码。不得裁切生成式图片假装地理边界。
- 手机端细小行政区域应有可点击的地区列表等替代入口；hover 不能是唯一入口；尊重 `prefers-reduced-motion`。地图仍须在低性能手机测试。
- 进入、退出府县以及日历↔地图跳转均保留日期／范围筛选，活动列表同步更新。

## 14. 地图已收录区域的四色独立高亮（2026-11-20，后续增量）

**新增设计决定与第13节的差异：**用户确认 PR #8 五色主题合并且实测无异常后，进一步要求：地图每个**有已收录记录**的区域，从紫、粉、蓝、白四色**独立随机**选一种填充，并在区域边界使用**金色描边**。这覆盖第13节“已收录地图区域仅紫色／金色只标示当前选区”的旧实施方式，但不改写当时的历史决策；当前有效规则以本节为准。

- 已收录区域：`#9862BC`（紫）、`#EFA1CC`（粉）、`#8EC8EF`（蓝）、`#FFFFFF`（白）任选其一；**金色 `#D8B764` 边框**。四色不代表活动类别、数量、重要程度或证据等级。
- 未收录区域：保持深灰 `#575665`，不随机填色，也不把空记录状态称为历史上没有活动。
- 选择状态：选中的已收录区域显示**更粗金色边框**；选中的未收录区域也维持原有金色选择提示，因此访客仍可通过填充色和图例区分「有记录」与「当前选中」。白色填充区域依靠金色描边与轻柔阴影保持可辨认。
- “随机”具体实现为以行政层级＋稳定行政代码为输入的**确定性伪随机散列**，每区独立赋色且同区跨筛选、刷新、返回保持颜色，不因每次重绘而跳色。不存在四种颜色平均分布、相邻区域必不重色的承诺；颜色无需存进活动 JSON。
- 全国都道府县与东京都二级区市町村分别按本级行政编码赋色；无论地图显示为东京本土、伊豆诸岛还是小笠原诸岛，同一行政区始终使用自己的颜色。只修改 `map.html`、`assets/theme-v12.css` 和相关文档，不修改地图几何或共享活动数据。
- 当前正式演示数据仅一条 Staff Talk，因此线上只会出现少数有记录的高亮区域；四色样式可通过离线隔离测试核对，不追加虚构活动来制造四种颜色。

**实施状态：**独立开发分支 `feature/map-multicolor-highlights`，拟建立 PR；合并和用户 PC/iPhone 实测须在实际发生后再更新状态。第13节仍保留初次五色主题的历史记录，避免事后覆盖方案演变。


## 15. 地图每次重绘重新抽色（2026-11-20，PR #9 后续修正）

**决策与取代范围：**PR #9 已于2026-11-20合并（`9351c00338055851a91c371c272dfc42481d8481`）。用户测试后否决其“行政编码决定永久颜色”的确定性伪随机机制；保留第14节认可的四色、已收录区金边、选中区更粗金边、未收录区深灰。第14节保留为历史版本，不再代表当前有效的随机行为。

**当前有效规则：**

- 每次载入、刷新地图，或页面交互导致 `draw()` 再次执行时，所有本轮参与绘制且有已收录记录的行政区重新独立抽取紫 `#9862BC`、粉 `#EFA1CC`、蓝 `#8EC8EF`、白 `#FFFFFF` 之一。
- `draw()` 创建一次性 `Map`，以“行政层级:行政代码”作为键；`geometrySVG()` 与 `regionHighlightColor()` 共享本轮映射。这样主图与冲绳缩略图等重复绘制的同一行政区在**同一次 draw** 中颜色一致；下次 draw 创建新 Map 并重新抽取。抽色使用 `Math.random()`，不保存到本地存储或共享活动 JSON。
- 不强制四种颜色均分，不禁止相邻区域撞色；每轮抽色后也**不保证颜色一定与上轮不同**。颜色不映射活动数量、分类、重要性或资料可靠性。
- 有记录区域统一使用金边；选中时金边更粗。无记录区域继续深灰，即使选中也不改变其“无已收录记录”语义；白色填充继续利用金边和柔和阴影识别。
- 不改动三页面导航和筛选数据流、地图行政边界 JSON、单条 Staff Talk 演示数据、布局及 V1.2 五色视觉体系。正式数据的真实性与公开授权边界保持原状。

**实施状态：**本次修正由 `fix/map-redraw-random-highlights` 独立分支提出，须经用户审查 PR、手动合并、GitHub Pages 部署与 PC/iPhone 实测才可记为已正式验收；代码静态及隔离逻辑测试与设备实测分开记录。

## 17. iPhone 地图可读性／跨区高亮错误（2026-11-20，PR #12 历史增量）

## 18. 圆角方块示意地图｜PR #13（2026-11-20，已合并并由用户报告验收）

### 决策来历与变化

用户先于 PR #12 实测反馈 iPhone 真实轮廓地图“变得很奇怪”，同时确认“点击无活动区块后有活动高亮消失”已解决。用户提供一张全国都道府县的矩形方块示意图参考，随后明确批准助手推荐：**不再保留 PC 真实轮廓与 iPhone 简图双实现，而是 PC 与手机统一采用圆角方块示意地图**。这样做是产品展示方式的决策变化，不是声称日本行政区划本身变成方块，也不是对旧版开发成果的否定。首页开发继续让位于本修复。

### 当前批准功能要求

- **全国第一层：**47个真实都道府县名称与代码，各用一个圆角方块；桌面参考大体方位以形成类似日本列岛的示意分布，手机使用按地方分组的三列自适应方块，禁止再次强制放大整个日本地图导致横向溢出或嵌套滚动。
- **东京第二层：**62个真实区市町村名称与代码，按23区（23个）／多摩（30个）／伊豆诸岛（8个）／小笠原诸岛（1个）分组。23区与多摩共处 `view=mainland`，伊豆 `view=izu`，小笠原 `view=ogasawara`；这是**浏览分组**而非新增行政层级。其他46府县不做虚构二级行政图。
- **颜色与交互：**无已收录记录始终深灰，有记录独立随机赋紫、粉、蓝或白，有记录始终带金边，选中区域金边加粗。每次重绘重新抽签，同轮单个行政区一致。点击其他无记录区只改变选中及活动预览，不抹除别处高亮。继续支持单日／整月、类型、行政区下拉、URL 回退与直接访问、日历与档案及纪念册跨页参数。
- **形状语义：**手工布局不按面积、实际相邻关系、比例尺或测量精度表示行政边界；须在页面提示。避免把参考截图当作真实行政地理数据或把参考图直接发布到网站。
- **维护数据：**`data/map-schematic-layout.json` 保存47府县的15列×14行桌面示意格与所有62东京行政区代码／名称／分组；源自仓库原47／62行政单元清单的交叉校对，仍需正式2026年行政区编码复核。原2025 N03 衍生 `data/map-prefectures-paths.json`、`data/map-tokyo-paths.json` 仅供历史追溯，不再被当前页面加载；保留其原出处和未决许可核验。
- **数据边界：**唯一演示活动仍是10月15日新宿 Staff Talk，不增补任何未经核验的公开史料、图片或模拟活动；主活动与多场次计数问题依第7—8节以后另议。
