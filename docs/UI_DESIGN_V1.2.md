- **产品定位与主要视觉方向：**已由用户认可。暂用名称「探Q活动回忆档案馆」，正式名称尚未最终确定。
- **当前技术基线：**GitHub 公开仓库 \`enhayato/star-detective-precure-web-lab\`；\`main\` 根目录 \`index.html\`；GitHub Pages 从 \`main/(root)\` 部署，已完成两次成功工作流部署。
- **本轮开发目标：**在独立分支实现可交互的静态响应式日历和活动预览卡。工作分支上的 UI **不等于**已经上线；须经 PR 审查并合并到 \`main\` 才进入正式站点。

## 1. 产品目标与边界

网站核心价值是让访客发现「原来 2026 年的那一天、那个地方，还发生过这种探Q活动」。**发现以前不知道的活动**是优先目标，重温本人参与过的活动是次要价值。访客主要是普通粉丝，不以研究人员为首要对象。

不是实时活动导航、购票、报名或预约系统；不承诺数据更新实时性和全国活动穷尽性；不提供精确商场楼层、路线规划或地点导航；首版不引入登录、收藏、管理后台或服务器数据库。

**必要语义：**「暂无已收录记录」不等于「当天／当地没有举办活动」。

## 2. 站点信息架构与交互关系

规划导航：**首页｜日历｜地图｜活动档案｜关于本站**。原型中未制作的入口应标明“开发中”，不可伪装成已可访问。

| 页面 | 核心用途 | 状态 |
| --- | --- | --- |
| 首页 | 两个主要入口：“按日期回看”“按地图探索” | 待实现 |
| 日历 | 2026 年按月／单日浏览，筛选、活动卡片 | 本轮原型 |
| 地图 | 全国 47 都道府县 → 真实市区町村等行政单元 | 待实现 |
| 活动详情 | 纪念册式图文介绍、来源、关联活动 | 待实现 |

## 3. 日历：设计与行为（已认可）

### 3.1 桌面和移动端

- 页面标题「2026年的活动日历」，以年月、地区、活动类型、单日／整月模式筛选。
- 桌面主体视觉比例约 70% 日历 / 30% 活动预览，具体宽度随屏幕调整；手机纵向堆叠，不照搬桌面双栏。
- 单格显示日期数字和简洁标记，**不在格内塞长标题**。选中日期采用明显紫色状态；有已收录条目的日期使用粉色小圆点。
- 选日期不跳页，右侧（手机下方）预览即时改变；进入活动详情才离开日历。
- 手机日期触控区域足够大；卡片标题、举办日期、地点优先可读。视觉稿中的虚构活动数不能照抄。
- 自定义日期范围属于后续范围；原型先实现单日／整月，并保留扩展位置。

### 3.2 日期语义

- 持续数日的同一活动，在覆盖的每个日历日期均可检索，但**不是多份独立活动主记录**。
- 同一活动在多个地点与日期的不同场次需要独立的举办实例，主活动和场次的唯一性／计数待制定正式规则。
- 日期按日本当地历日 \`YYYY-MM-DD\` 处理，不应因为 UTC 转换发生日期偏移。
- 年月、日期、地区、类型以及跨页状态应能从 URL 恢复；当前原型只实现日历页内部 URL 状态，地图尚未接入。
- 没有标记的日期意味着「当前筛选范围内无已收录记录」，不是历史上不存在活动。

## 4. 地图：必须保留的 V1.2 约束（尚未实现）

- **第一级：**日本 47 都道府县真实边界，以时间过滤后的已收录活动状态高亮。
- **第二级：**所选府县真实行政区划。东京都要细到新宿区、杉並区、渋谷区、世田谷区、豊島区，以及多摩各市町村、岛屿各町村等；其他府县保持合理一致的真实行政单元规则。
- 明确否决「东京23区西部／东部／多摩」等人为粗分区；只保留两级地理浏览，不下钻街道／商场／店铺。
- 无已收录活动的区域使用**深灰**；有记录的区域使用紫／粉／蓝亮色；选中区域边界更清楚，并可加入柔和静态外发光与克制的交互动效。
- **紫粉蓝具体映射规则尚未确定**；视觉稿示意中的“1—2、3—5、6+”和高亮地区、数量不是事实或已经批准的数量级。
- 正式地图使用**有许可依据、可核对的真实日本行政区划 SVG／GeoJSON 或等效边界数据**，记录来源、版本、授权方式及行政区代码。不得裁切生成式图片假装地理边界。
- 手机端细小行政区域应有可点击的地区列表等替代入口；hover 不能是唯一入口；尊重 \`prefers-reduced-motion\`。地图仍须在低性能手机测试。
- 进入、退出府县以及日历↔地图跳转均保留日期／范围筛选，活动列表同步更新。

## 5. 视觉设计基线（用户认可的是方向，不是精确像素）

**轻量卡通＋侦探手账＋清爽留白**，以功能为中心。保留少量放大镜／侦探元素、圆角、极浅阴影；不再使用 V1.0 的满屏云朵、胶片、重复星星、纸胶带、城市剪影或角色剪影。日历／地图／详情共用字体层级、按钮、导航和卡片样式。

| 角色 | 候选色值（均可调整） |
| --- | --- |
| 主紫（操作与选中） | \`#9862BC\` |
| 粉（活动标记与高亮） | \`#EFA1CC\` |
| 蓝（辅助高亮） | \`#8EC8EF\` |
| 地图无已收录数据区域 | \`#575665\` / \`#5B5969\` |
| 白／奶白背景 | \`#FFFFFF\` / \`#FAF9FC\` |
| 深紫灰文字 | \`#2C3041\` / \`#49345B\` |

配色的**色系、对比和柔和感**是已认可的方向；HEX 尚未锁定。发光强度、动效时长仍待原型测试。

## 6. 活动详情：纪念册，而非研究卡

显示活动主视觉（有合法使用依据时）、名称、日期时间、举办地点、简明介绍、出演者／形式（来源支持时）、相关图片、官方来源及相关活动。避免把内部审计编号和长篇研究论证作为访客主要体验。无图活动的默认卡片形式待确定。素材使用范围和权利仍须验证。

## 7. 数据与治理边界

网站数据来自独立的产业联动与活动研究工程，但**不取代**其权威数据库，也不直接公开全部内部调查字段。可考虑三层：①活动主档 ②场次／地点 ③公开展示视图。正式 schema、分类、导入频率、跨日／跨地区去重规则均尚未批准。

当前唯一真实演示候选：**2026-10-15《映画名探偵プリキュア！》Staff Talk**（新宿バルト9；人员等细节参见既有制作访谈与公开证言资料库）。本记录已在内部史料导航定位，但正式公开前仍须独立核实官方活动公告、具体时刻以及素材权利；示意数据不得冒充全站完整收录。

内部资料：[探Q制作访谈资料库总导航](https://docs.google.com/document/d/1-gn6JT-kWmxOgmHX2gjeEsH4tHS5a7EiKEvBzC9704w/edit)。链接仅供维护时回查，不是网站必须公开的入口。

## 8. 待决策清单（不得擅自改成“已决定”）

1. 网站的最终名称、Logo 和正文是否中日双语。
2. 活动类别与公开收录范围（线下／线上／全国活动／宣传）。
3. 活动主档与场次的计数、跨日／跨地去重、日期例外。
4. 地图行政编码、边界数据来源、许可证、更新频率和体积。
5. 紫粉蓝与事件数量／类型的关系，以及发光与移动端性能降级。
6. 事件海报和活动照片使用许可、无图封面。
7. 正式数据导出与更新方式；从研究库到公开发布的人工审核机制。
8. 访客更正联系机制与版权声明。

## 9. 维护和验收

**修改流程：**从最新 \`main\` 创建分支 → 仅改必要文件 → 在分支测试 → PR 查看差异 → 用户确认合并 → GitHub Pages 工作流成功 → 手机和电脑复核。禁止在未经许可时直接修改正式研究主档或覆盖 \`main\`。

日历原型验收至少包括：2026 年月切换、单日／整月、已有记录标记、筛选空状态、浏览器返回和刷新保留筛选、手机不横向溢出、无外部资源仍能显示基本页面。地图另行验收真实地理边界和许可证。

**版本历史：**V1.0 过度装饰（弃用）→ V1.1 轻量化（认可）→ V1.2 深灰未收录区域、紫粉蓝光效、真实行政区二级地图（认可）。本轮日历代码只是对 V1.2 的部分工程实现，不自行变更这些历史决策。
