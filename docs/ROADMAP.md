## 1. 当前基线和接续顺序

- 站点目的：面向普通《名探偵プリキュア！》粉丝，帮助发现和回顾2026年已发生的活动；不是实时活动导航、报名入口或完整收录承诺。
- 部署：静态 HTML、CSS、JavaScript；GitHub Pages 从 `main/(root)` 发布。所有实际改动从最新 `main` 建独立 Branch → 中文 PR → 用户审查合并 → Pages 部署 → 用户 PC/iPhone 验收。禁止自动合并、直接改 `main` 或跳过用户的设备验收。
- **已完成的主要功能：**活动日历 `index.html`、活动地图 `map.html`、活动档案 `archive.html`、纪念册 `event.html`、独立首页 `home.html`（PR #15）、关于本站 `about.html`（PR #16）。PR #4—#12 历史及其状态见 README／UI 规范。
- **当前有效地图（PR #13）：**全国47都道府县及东京62区市町村使用圆角方块示意地图，PC/iPhone 响应式布局；2026-11-20 PR #13 已合并，用户报告设备验收通过。未收录深灰、有记录四色重新抽签、金色边框、选中加粗及跨页状态传递继续有效。**这是主要浏览地图，不因第3节远期候选而撤销**。
- **数据真实性边界：**当前公开原型只有一条2026-10-15新宿 Staff Talk 演示数据 `data/events-demo.json`，尚未接入正式产业研究数据库，不能由它推论实际活动数量、覆盖区域或最早公告日。发布级来源、日期、场次及图像授权仍待逐项核验。
- 旧日本行政边界衍生 JSON 保留用于历史追溯，当前方块地图不调用；若未来重新用于公开展示，必须重新核查版本、来源、许可／再利用条件及移动端表现，见 `docs/MAP_DATA.md`。

**下一次接续：**先读 README 与本文件 → 查最新 `main`、开放 PR 和 Pages → 按第2节确定下一项 → 阅读相关 UI／数据细则 → 从最新 `main` 建分支执行。不要从历史 PR 标题或旧设计状态推断当前已批准功能。

## 3. 远期增强候选｜《探Q活动时间演化地图》

**登记日期：2026-11-20（JST）。来源于 PR #13 方块示意地图完成合并并由用户验收后的新构想；不属于最初 V1.2 已批准需求。**

### 3.1 动机与产品定位（仅为候选构想）

PR #5—#12 的真实地理轮廓地图具有地理实感，但在 iPhone 上地图太小；改用手机内部双向滚动放大后，又牺牲页面布局与可用性。因此 PR #13 确立了**方块示意地图作为日常地区查询工具**的有效方案。

在保留这一方案的前提下，用户提出未来**另外增加**一张具有真实日本地理轮廓的时间演化展示：访客可点击播放，让日期从2026年探Q活动最早的**真实公告日期**起按一定节奏逐日推进，地图上的相关地区随已收录活动资料而发生高亮／熄灭或其他变化，帮助直观看到当年的活动如何在不同地区展开。

这一表述是**设计意图**，并非已确认的日期起点、显示算法、页面布局或实现规格。

| 两种地图 | 主要目的 | 状态 |
| --- | --- | --- |
| **现有方块示意地图** | 日期／类型／地区筛选，快速寻找档案，手机友好 | 当前已验收的**主要浏览界面** |
| **未来真实轮廓时间动画** | 展示活动公告传播或实际举办的时空演化，偏视觉回顾 | **远期研究候选**，与主地图并存、不替换 |

### 3.2 待研究、待决定（非功能规格）

1. **时间轴的统计对象：**公告首次发表日、活动实际举办日，还是可切换双轴？两者回答的问题不同。最初构想虽提到「从最早公告日开始」，但**最早公告日期尚未查实**；不得猜测或由一条演示数据倒推。
2. **点亮语义：**仅举办当日亮起、首次出现后持续累计亮起，还是允许切换？若采用「公告轴」，公告地区与实际举办地区的映射、未来活动预告是否提前点亮也必须定义。
3. **播放交互：**推进速率、播放／暂停／重播、是否拖动时间轴、当前日期和事件信息的显示位置及方式；都未决定。
4. **视觉规则：**是否沿用紫／粉／蓝／白及金边未定；现有“每次地图重绘随机抽色”适合方块浏览，却可能造成逐日动画中的无意义闪烁，必须独立评估颜色持久性和视觉语义。
5. **真实地理数据与设备体验：**选择哪种行政边界、行政层级、版本与许可；PC 与 iPhone 的展现差异；缩放、离岛、可访问性、性能和浏览器兼容性。现存2025 N03衍生轮廓文件**不等于已获准直接复用**，也不能据此认定2026年的边界已核准。
6. **活动数据建模：**公告日与举办日独立；主活动／场次／地区及跨日、多地点、多轮公告、修订／取消如何映射和去重；数据不完整时怎样标示覆盖限制。未来需在正式数据公开视图审核完成后再确定可视化所需的数据转换，不直接公开内部核查字段。
7. **统计与误读边界：**彩色覆盖不自动等于实际活动覆盖率、商业效果或全国已穷尽调查；动画须明确仅呈现**当时已经收录且通过相应审核**的活动记录。
